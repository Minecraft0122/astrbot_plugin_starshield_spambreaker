# 星盾·刷屏终结者

这是一个 AstrBot 反刷屏插件。它不依赖“同一内容累计发送 5 次”这种容易绕过的计数，而是按平台、会话和发送者分别维护有限历史，检测以下情况：

- 同一用户在短时间窗口内再次发送已放行过的完全相同消息时拦截。
- 消息主体基本相同、只在末尾追加随机字符，且发生在短时间窗口内，按近重复拦截。
- 单条消息包含大量连续重复片段，例如 `神经病神经病神经病神经病`。
- 同一用户在短时间内发送多条长消息，达到配置阈值时拦截当前消息。
- 内置及自定义中文违禁词和其拼音写法。
- 纯空白消息和连续空行达到阈值的消息。

命中后会调用 `event.stop_event()`，阻止后续插件和 LLM 继续处理。启用撤回时，`aiocqhttp` / OneBot 适配器会调用 `delete_msg`；QQ 官方文字子频道会调用官方 `recall_message`。只尝试撤回当前命中的新消息，失败会记录日志，拦截继续生效。

### QQ 官方 Bot 的能力与验证

QQ 官方 Bot 的 WebSocket（`qq_official`）和 Webhook（`qq_official_webhook`）收到的文字消息均走相同检测逻辑。插件使用可匹配空文本、多行文本的全消息正则入口，以高优先级运行；命中后停止后续事件处理，并调用 `should_call_llm(True)` 禁止本事件的默认 LLM 请求（AstrBot 的该参数表示“禁止”，不是“启用”）。默认不发送拦截提示。

v1.10.0 起支持 **QQ 官方文字子频道** 的违规成员消息撤回，开启“启用撤回”即可。机器人需要具备相应频道管理权限及 API 权限：管理员可撤回普通成员消息，频道主可撤回所有人消息。WebSocket 与 Webhook 使用相同 SDK 接口；请求超时、权限不足或接口不可用时，不会把撤回记录为成功，也不会解除消息拦截。

**QQ 普通群、单聊和频道私信无法通过公开官方接口撤回用户的违规消息。** 官方公开的普通群和单聊 DELETE 接口仅支持撤回机器人自己发送、且未超过 2 分钟的消息；频道私信也仅支持撤回机器人自己的消息。因此，这些会话仍只阻止机器人继续处理，并输出能力限制日志，不会把群号当作频道 ID 误调用频道撤回接口。依据：[腾讯官方撤回接口文档源码](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/reset.md)、[官方 Python SDK 的频道撤回说明](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/pythonsdk/api/message/recall_message.md)。

验证时可打开“发送拦截提示”（`enable_block_notice`），保存并重载插件，再向机器人发送词表中确实存在的词（如 `fuck`）。启动日志 `ready version=... keywords=... pinyin=... block_notice=...` 显示实际生效设置。每次进入检测都有 INFO 级别的 `inspect platform=...` 记录，不记录正文；命中日志包含 `blocked spam reason=banned_keyword`、平台名称与消息 ID，开启提示后还会尝试回复原因。

AstrBot 的“收到消息”日志早于插件执行，因此它不能证明本插件已经运行。在 AstrBot 4.28.2 中，插件选择（`plugin_set`）、会话内禁用列表（`disabled_plugins`）、会话白名单、会话停用、框架限流或前置安全检测，都可能使消息在本插件执行之前被跳过。如果有框架收消息日志但没有 `inspect`，应检查该消息实际匹配的配置文件是否选中了 `astrbot_plugin_keyword_matcher`，以及该会话的插件启用状态和上述前置限制。插件会遵守这些设置，不绕过管理员禁用。`EventMessageType.ALL` 在该版本也支持 QQ 官方消息；不能仅凭缺少日志归因于消息类型枚举。

v1.9.6 起，启动时还会输出 `routing registered=True active=True handler_enabled=True bound=True` 和 `routing profile='default' selected=True` 等诊断记录。`registered=False` 表示未找到入口；`bound=False` 表示未绑定到当前实例；`selected=False` 表示该配置的插件筛选不会选中入口。诊断还会输出过滤器、权限和会话白名单的启用状态及数量，不输出白名单内容。若这些状态正常但仍没有 `inspect`，将 AstrBot 核心日志级别切到 DEBUG 后重发，结合 `enabled_plugins_name`、`plugin ->` 和 `Stage ... stopped event propagation` 定位消息被跳过的具体步骤。

拦截只影响执行到本插件之后的 AstrBot 处理；优先级高于本插件的其他处理器、框架前置步骤和平台侧行为不在此范围内。提示发送也受官方接口权限和频率限制，发送失败会记日志，不会解除拦截。

## 安装

将插件目录放到 AstrBot 的 `data/plugins/astrbot_plugin_keyword_matcher` 下，在 WebUI 中重载插件或重启 AstrBot。

## 默认策略

- 完全重复：同一用户最近 60 秒内任意一条已放行消息在规范化后相同即命中。规范化会处理 Unicode 兼容形式、大小写、连续空白和零宽/控制字符。
- 随机尾缀：默认只回看 60 秒内的近期消息；主体至少 12 个字符，公共前缀至少占较短消息 75%，差异尾部总计不超过 64 个字符，并且尾部符合常见随机 ASCII/Unicode 标记特征；即使尾缀只有 1～3 个 ASCII 字符，只要每条消息都在变化也会拦截。
- 单条重复：同一片段连续出现至少 4 次、总重复长度至少 12 个字符，并覆盖消息至少 60%。
- 长消息突发：默认 10 秒内第 3 条及后续至少 300 字符的消息会被拦截。被拦截的消息不会计入后续历史。
- 空白内容：纯空格、换行、制表符等消息会被拦截；正文中连续空白行默认达到 5 行时拦截，阈值可由 `max_consecutive_blank_lines` 调整，也可通过 `enable_blank_message_detection` 关闭。

所有检测阈值都可以在插件配置页调整。`max_recent_messages`、`max_senders` 和缓存过期时间用于限制内存使用。

## 违禁词与拼音检测

在插件配置的 `banned_words` 列表中逐项填写中文关键词。列表默认已经写入内置辱骂、作弊和广告词库，可以直接添加、删除或批量导入。原文检测始终按词表生效；`enable_pinyin_keywords` 只控制额外的拼音和中文同音检测。多音字按有限组合展开，组合上限由 `pinyin_max_combinations` 控制。关键词之间插入换行、空格、标点、数字或常见形近字母时也会按紧凑形式检查，例如 `调\\n教`、`调1教`、`ѕhаbi`。检测优先使用原始顶层 Plain 消息段，避免框架裁剪首尾空白或移除唤醒前缀后漏检。此功能不代表完整的语义审核。

拼音连续拼接也会检查，例如配置 `傻逼` 时 `nihaoshabi` 会命中；中文同音词只按完整连续汉字片段比较，避免把 `干嘛的` 误判成配置词 `妈的`。

从旧版本升级时，插件首次加载会把预设词与现有自定义词合并，旧的多行文本也会转成列表，然后通过 AstrBot 保存配置。重载插件后重新打开配置页即可看到预设词；后续删除词条或清空列表会被保留。需要再次补入预设词时，打开“下次加载补入预设违禁词”并重载插件，该选项完成后自动关闭。

默认词库不再包含 `外挂`、`作弊`、`垃圾`、`滚蛋` 四个宽泛词，以减少正常讨论的误判，仍保留 `出售外挂` 等具体词条。与旧版默认词库完全一致的列表会自动替换成新词库；定制过的列表不会删除已有词，如果其中有这些宽泛词，需要手动移除。词表采用包含匹配，不判断上下文，引用或讨论具体违禁词仍可能被拦截。纯标点词条仅按原文匹配，不会因去除标点后为空而匹配所有消息。

## 说明

“随机尾缀近重复”只比较时间窗口内近期消息的公共前缀，不会删除原文，也不会把任意数字或英文内容一律当作随机字符。因此正常的不同问句、版本号或邀请码仍有机会被区分；如果实际群聊内容更短或更长，可以调低/调高 `near_duplicate_window_seconds`、`near_duplicate_min_chars`、`near_duplicate_prefix_ratio` 和 `near_duplicate_max_suffix_chars`。

单条重复检测采用有界周期扫描，不使用可能发生灾难性回溯的正则表达式。超长消息只扫描有限的首、中、尾部分。

## 测试

安装 `requirements.txt` 中的依赖后运行 `python -m unittest discover`。默认测试不需要启动 AstrBot。

需要验证框架调度语义时，检出 AstrBot 的 `v4.28.2` 标签，将环境变量 `ASTRBOT_SOURCE` 指向其根目录，然后运行同一命令。额外测试会加载上游注册器、唤醒检查、会话插件筛选、插件执行和默认 LLM 判断源码，替换外部服务依赖后运行；未设置该变量时会跳过。这不等同于真实 QQ 平台联调。
